## 图标使用场景
#SSH识别到的系统，展现系统图标
#识别到系统安装的服务，当服务为WEBUI时，会展现在对应服务的卡片中

# OpsNest 图标目录

```text
icons/
├─ packed/
│  ├─ systems/   # 随桌面程序打包的系统图标
│  └─ services/  # 随桌面程序打包的常用服务图标
├─ systems/      # 可在线追加的操作系统图标
└─ services/     # 在线服务、内置APP图标，按稳定 ID 直接查找
```

## 命名规则

- 文件名使用稳定的英文 ID，例如 `openlist.png`、`1panel.png`、`debian.svg`。
- 禁止使用 `logo1.png`、`logo(1).png` 等依赖顺序的编号名称。
- 程序不依赖额外索引文件；文件名就是稳定 ID。
- 服务识别使用服务器返回的服务 ID、进程名或服务名称进行规范化。
- 版本专属图标可以使用 `name@major.minor.svg`。例如 `ubuntu@24.04.svg`。

## 尺寸与文件大小

- 图标必须是正方形，宽高相同。
- PNG 最小尺寸为 `64 × 64 px`，最大尺寸为 `1024 × 1024 px`；推荐使用 `256 × 256 px` 或 `512 × 512 px`。
- SVG 必须使用正方形 `viewBox`，建议坐标范围为 `0 0 24 24`、`0 0 48 48` 或 `0 0 512 512`。
- `packed/` 目录只允许使用 SVG；PNG 不进入桌面程序包，统一放在 `icons/services/` 或 `icons/systems/`，由运行时线上读取。
- 单个图标文件最大为 `100 KB`；放入 `packed/` 随桌面程序发布的图标也必须遵守此限制。
- 图形主体建议占画布的 `75%–90%`，避免四周出现过多留白；透明背景可以保留。
- 优先使用 SVG；只有软件官方只提供位图，或 SVG 无法准确表达时才使用 PNG。
- 不接受截图、带水印图片、非正方形图片和依赖文件名顺序的图标。

## 加载方式

1. 优先使用 `packed/` 中随 EXE 发布的图标。
2. 没有内置图标时按服务 ID 直接读取线上目录。
3. 先查找版本图标，再查找通用图标。
4. 下载成功后缓存在本地，断网时继续使用缓存或内置 fallback。
