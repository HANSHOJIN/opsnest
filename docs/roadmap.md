# OpsNest Roadmap

这份路线图记录已经确认的开发方向。优先级会同时考虑用户体验、实际使用价值和安全边界。

## P0：当前 Agent 基础能力

- AgentRun 根据命令结果持续调整下一步
- 执行结果的自然语言总结
- 服务器记忆与会话上下文
- 命令失败后的有限恢复
- 命令、结果和审批记录的本地审计

## P1：服务器文件管理

目标：在 SSH 会话之外，提供类似 Workbench 的文件管理能力，让新手不用手写 `scp`、`sftp` 或 `cp` 命令。

第一阶段：

- 浏览当前目录和目录树
- 查看文件名、大小、修改时间和权限
- 返回上级目录、进入目录
- 文本文件预览
- 文件搜索
- 上传文件到当前目录
- 从服务器下载文件
- 显示上传/下载进度和失败原因

第二阶段：

- 创建目录
- 重命名文件和目录
- 删除文件和目录
- 编辑并保存文本文件
- 文件权限查看与修改
- 压缩与解压

安全规则：

- 删除、覆盖、权限修改必须确认
- 默认显示目标路径、影响范围和文件大小
- 上传覆盖已有文件时必须二次确认
- 不把文件内容默认发送给模型
- 文件操作保留完整本地审计记录
- 大文件传输支持取消和失败重试

## P1：服务器卡片快捷安装

目标：在服务器 Dashboard 卡片中提供“快捷安装”菜单，把常用软件安装变成可审查的任务，而不是直接执行隐藏命令。

首批候选：

- Docker
- Git
- Nginx
- Caddy
- Node.js
- Python
- Certbot
- `docker compose`
- 常用监控工具：`htop`、`btop`

交互流程：

```text
服务器卡片
  → 快捷安装
  → 选择软件
  → 检测系统与包管理器
  → 展示安装计划和预计影响
  → 用户批准
  → 执行安装
  → 验证版本与服务状态
  → 保存结果到服务器记忆
```

实现要求：

- 根据 Debian、Ubuntu、CentOS、Alpine 等系统选择安装策略
- 安装前检查系统版本、权限、磁盘空间和网络
- 明确使用 `apt`、`dnf`、`yum`、`apk` 或官方安装源
- 显示将执行的命令，但不要求新手理解命令
- 安装任务必须经过批准
- 安装完成后自动验证版本和服务状态
- 失败时说明失败阶段，不盲目重复安装
- 每个安装项使用版本化任务模板，避免完全依赖模型自由生成

快捷安装菜单不应成为“万能 Shell 菜单”。模型可以帮助解释和处理异常，但基础安装流程应由 OpsNest 的受控任务模板负责。

## P2：文件与任务联动

- “上传并部署这个文件”任务
- “查看这个配置文件并解释”任务
- “修改配置、备份原文件、验证并回滚”任务
- 文件变更前后对比
- 部署任务时间线

## P2：更完整的 Agent 工具层

- 将文件操作、服务操作、软件安装收敛为参数受限工具
- 工具声明风险等级、权限要求和回滚能力
- 动态工具发现，而不是一次暴露全部工具
- 支持任务暂停、恢复和取消
- 支持任务中途修改计划

## 暂不纳入近期范围

- Kubernetes 全面管理
- 无人值守批量生产变更
- 云端凭据同步
- 团队协作和多租户
- 自动修改防火墙和安全组
- 自动删除、格式化和数据库破坏性操作
