# Live Host Telemetry 开发计划

记录日期：2026-10-02。状态：已纳入路线图，仅规划，尚未实现。

## 产品目标

用户打开服务器后，第一眼即可判断机器当前是否健康，并理解最近一次操作对资源的影响。

Live Host Telemetry 是 SSH 会话旁边的实时生命体征。OpsNest Desktop 继续负责终端、文件、AI 操作和本地记录，新增独立 Monitor Channel，由 OpsNest 轻量 Agent 采集和上报指标。

确认的边界：

- OpsNest Agent ↔ OpsNest Desktop，不依赖 Beszel Hub、额外云端服务或数据库。
- 可以研究 Beszel 的轻量 Agent 和采集思路；复用代码前核实许可证、平台支持和维护成本。
- 保持“下载 exe、输入服务器连接信息即可使用”的体验；监控是可选增强。
- 不要求用户安装 Docker 或理解 systemd、WebSocket、/proc、/sys。
- 保持现有服务器页面的克制感，以紧凑指标、短趋势和展开详情为主。

## 首次启用

首次成功连接且未启用监控时，提供可关闭的提示：“启用实时硬件监控？”和“一键安装轻量 Agent”。

用户主动启用后，经现有 SSH 完成：

1. 检测系统、CPU 架构、服务管理器和安装权限。
2. 选择匹配的受信任发布二进制，校验后上传。
3. 设置执行权限，建立服务器与 Desktop 的配对。
4. 注册后台服务并启动；systemd 首先适配，其他服务管理器分期支持。
5. 建立监控连接，验证身份和采样，再显示“实时监控已启用”。

安装前简短告知会新增后台服务和资源采样，不把内部命令变成用户必填配置。安装沿用本地凭据与提权流程，不要求向模型提供密码。

安装失败显示失败阶段并允许重试，保留现有 SSH 使用能力。重复启用不重复注册服务。提供停用、升级、卸载入口，升级保留配置和配对，失败可回退。

## 通道与生命周期

Agent 主动上报，Desktop 接收指标。首选利用已认证 SSH 建立独立通道或隧道，承载 Monitor Channel；具体协议在原型阶段验证后确定。不能假定 Desktop 有公网地址，也不能把开放防火墙、端口映射或部署 Hub 变成前置要求。

- 采样、传输和重连独立于 PTY 输入、命令执行锁和 AI 请求循环。
- Agent 只提供指标，不接受任意命令执行；尽量以最小权限运行，增强指标按需授权。
- 配对、缓存和事件绑定稳定服务器 ID，验证连接身份与协议版本，避免多服务器数据混用。
- 页面切换不重新安装 Agent，也不销毁已启用的监控通道。
- SSH 传输断开可以导致监控失效，但监控失败不能把仍连通的 SSH 误标为失败。
- Desktop 离线时退避重连、保持有界缓存；不无限堆积数据，不隐式上传云端。
- 显示采样时间、数据年龄、未连接和过期状态，旧值不能冒充实时指标。

## 指标与界面

默认概览采用固定布局的紧凑行：

| 指标 | 展示 |
| --- | --- |
| CPU | 利用率和短趋势 |
| Memory | 利用率、已用 / 总量、可用内存 |
| Disk | 文件系统使用率、已用 / 总量 |
| Network | 下载和上传速率 |
| Load | 负载与 CPU 核数参考 |
| Temperature | 可读取传感器的温度 |
| Uptime | 系统运行时间 |

下面按需展开 CPU cores、Disk IO、Network interfaces、Docker、GPU、Processes。复用现有服务器详情页和 Shell 风格，不新增一套导航或满屏图表。

明确 Linux 内存缓存与可用量口径、网络速率采样区间、磁盘挂载点筛选和 Load 核数归一化。缺失的温度、GPU 或权限不足的指标显示“不支持 / 无权限”，不能显示为零。健康判断结合持续时间与资源余量，不把瞬时 CPU 高峰直接判为故障。

原型建议以 3 秒为默认采样间隔，提供低频选项；最终间隔和开销预算通过实测确定。Desktop 为每台服务器保留有界近期趋势，长期历史另列后续需求。

## 操作关联与 AI

复用 Activity timeline，按服务器和时间关联指标变化与 SSH / AI 操作，例如：

- 11:32：执行 docker compose up。
- 11:33：CPU 18% → 92%。
- 11:34：Memory 2.1 GB → 5.8 GB。

记录服务器 ID、采样序号、Desktop 接收时间和 Agent 采样时间，处理时钟偏差与断线缺口。呈现“操作之后发生变化”的证据，不直接宣称操作一定是原因。

后续增加只读指标工具，让 AI 回答“服务器怎么这么慢”时读取当前资源、短期趋势、主要进程和容器情况。工具返回新鲜度和不可用字段；必要时通过现有 SSH 工具进一步核实。

仅在用户请求诊断或当前任务需要时提供有限指标摘要，不持续向模型发送原始指标流、完整进程参数或文件内容；指标不得携带 SSH 密码、API key 等凭据。

## 分期与验收

### T1：轻量原型与概览

先选受控 Linux x86_64 主机，验证自有 Agent、SSH 内监控连接、协议版本与重连。提供 CPU、内存、磁盘、网络、Load、Uptime；温度按能力探测。Desktop 展示紧凑概览与过期状态。

验收：与系统工具在相同口径下核对采样；启停、断网和页面切换不影响终端输入；缓存有界；采样开销经实测可接受。

### T2：一键启用与扩展指标

完善安装、停用、升级和卸载，增加 Linux ARM64、Docker、CPU cores、Disk IO、主要进程和传感器详情。OpenWrt / iStoreOS、NAS、非 systemd 环境按设备逐项适配；GPU 单独评估驱动和权限。

验收：新手只需主动点击启用；重复安装、权限不足、架构不支持、升级失败均有可理解的结果；Docker 不存在不阻止其他指标使用。

### T3：操作关联与 AI 诊断

关联 Activity timeline，支持操作前后指标对比；接入只读指标工具，根据资源和进程数据辅助诊断。

验收：多服务器隔离；时间偏差、断线和过期样本可识别；AI 不编造指标、不把时间关联当作已证实的因果关系。

## 实施时机与首轮范围

功能冻结的重构阶段结束后，再拆分本计划进入功能开发。本次不修改运行代码、版本号或 Release。

首轮不包含 Beszel Hub、独立监控后台、Grafana 风格大屏、云端指标上传、多租户、长期时间序列数据库、全天候告警平台，以及依据阈值自动修改服务器。
